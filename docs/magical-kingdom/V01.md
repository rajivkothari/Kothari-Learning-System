# Princess Vienna's Magical Kingdom — V0.1

This review prototype has three environments: a castle with three interactive doors, an Ice Palace crystal bridge, and a Royal Garden letter flower. Dress-up changes a small accessory color. Castle stars and flowers respond to touch without recording learning evidence.

## Play

From this feature checkout, use Node 24 and run:

```powershell
npm ci
npm run web:export
node scripts/serve-web.js dist-web --port 8093
```

Open `http://localhost:8093/?open=kingdom` (alias: `?open=vienna`). The developer launcher also offers MAGICAL KINGDOM. This is a local review build; ordinary production exports continue to open Elevator Quest and exclude the pending kingdom artwork.

Enter the blue Ice Palace door. Drag or tap five crystals onto the bridge. Tap a placed crystal to take it back. Make magic checks the construction, then the fox crosses and Back to castle returns home. Subsequent bridges vary from one to ten.

Enter the flower door. Drag or tap the first letter of the pictured word, then Make magic blooms the flower. Both activities work without a keyboard. Help me progresses through a clue and a guided hint; after two wrong attempts, Show me places the solution. Assisted answers keep their actual assistance classification.

The crown opens comfort controls. Sound and motion can be changed independently. New adventure book requires a second intentional tap and preserves prior evidence, costume color, and comfort choices. The castle icon returns from an activity or leaves the kingdom from the hub. Partial constructions and celebrations survive reload.

## Visual direction and character proposal

Warm handpainted storybook rooms share lavender, cream, turquoise, blush, and gold. Large seals identify each door. Lumi, a friendly smiling star, guides the child. Vector crystals, letters, flowers, and controls remain legible over the illustrated world.

The supplied Princess Vienna Valentina character name is branding from the assignment. The single concept depicts an invented cartoon princess with chestnut side braid, brown eyes, a lavender practical dress, turquoise sash, gold boots, and a small crystal crown. No photograph or real likeness reference was used. Please review this concept before a larger pose or costume set is produced. The current greeting pose uses a gentle bob and a small celebration response; it is not a finished character animation set.

All four PNG concepts were generated with the built-in image generation tool and copied unchanged into `assets/themes/magical-kingdom/`. Their status is **pending human art review**. [Art briefs](ART_PROMPTS.md) and the asset provenance JSON document the concept set. The interaction vectors are authored in `ui/MagicArt.tsx`; they are intentional game pieces, not claimed to be finished raster illustrations.

## Small shared-platform changes

- `App.tsx`: one lazy second-game route and one developer launcher choice.
- `metro.config.js` and `scripts/check-bundle.js`: exclude the prototype and its review artwork from ordinary production exports; check the kingdom marker.
- `package.json` and lockfile: SDK-matched `expo-speech ~57.0.3` for optional narration.
- `.gitattributes`: enforce LF on two existing generated Elevator runtime JSON files, whose exact serializer comparisons otherwise failed on this Windows checkout. Their parsed content did not change.

The second game's director, content, UI, gestures, and narration live under `src/themes/magical-kingdom/` and `content/themes/magical-kingdom/`. It uses the existing KLS generators, mission runtime, assistance policy, event transactions, and database adapter. There is no engine refactor or new persistence schema. A separate `kls-magical-kingdom.db` protects Elevator's save and content cache; learner identifiers remain archetypal. Restart creates a new learner generation rather than deleting evidence.

Only an explicit Make magic submission can produce an academic attempt. Decorative play, object placement, dress-up, navigation, and demonstration alone do not. Rewards come from completed missions. The Garden prints the word alongside its picture: it is **cued picture-word beginning-letter practice**, not proof of uncued phonemic awareness.

## Verification and limits

[QA report](../../qa/magical-kingdom/QA-Report.md) and [32-image gallery](../../qa/magical-kingdom/index.html) carry the recorded checks. Browser testing covers iPad and Fire viewport sizes in both orientations; it does not substitute for testing physical tablets.

Gameplay uses local persistence and requires no remote requests after assets load. The browser export is not a service-worker installation: a fresh offline page load is not established. Native speech depends on installed OS voices and has not been listened to on a device. Web narration selects an English voice only when it explicitly reports `localService: true`; no local voice means visual-only play. No music or bespoke sound-effect pack is included.

The speech API was checked against the official [Expo SDK 57 speech documentation](https://docs.expo.dev/versions/v57.0.0/sdk/speech/) (bundled version ~57.0.3), and the browser local-voice condition against [MDN localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService). The same authored vector paths use SVG in the browser, avoiding per-icon GPU contexts, and the repository's Skia renderer on native.

This slice does not include shapes, patterns, addition, ten rooms, a full wardrobe, or a broad curriculum. Child usability, native screen readers, real tablet performance, OS interruptions, and native voice quality still require device review.
